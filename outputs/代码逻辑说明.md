# 代码逻辑说明

本文对应 `eastmoney-all-a-intraday.user.js` 3.1.0。

## 1. 总体设计

脚本不直接修改东方财富原来的 ECharts 实例，而是在成交额图上覆盖一张透明 Canvas，再在 Canvas 中绘制指数分时线，同时在图内顶部放置“全A等权 / 平均股价”切换按钮。

```text
东方财富成交额 ECharts
          ↓ 保留原图和原提示框
透明 Canvas 绘制指数分时线
          ↓
顶部按钮切换全A或平均股价
```

采用透明覆盖层主要是因为页面中的 ECharts 实例由网站自己的前端框架管理。直接修改它的 `series` 容易在页面重新渲染时被覆盖，也容易受网站打包方式变化影响。独立 Canvas 不改变原图数据，出错时也不会影响原页面。

成交额和指数的单位不同：成交额使用亿元或万亿元，指数使用点数。因此两者只共用时间横轴，指数使用脚本单独绘制的涨跌幅右轴，不会拿指数点位硬套成交额纵轴。

## 2. 用户脚本声明

文件第 1～12 行是 Tampermonkey 元数据：

- `@match`：只在 `https://emrnweb.eastmoney.com/nxfxb/home` 页面运行；
- `@grant GM_xmlhttpRequest`：使用油猴提供的跨域请求能力读取行情；
- 三个 `@connect`：允许访问主行情域名和两个备用域名；
- `@run-at document-start`：尽早启动脚本，减少页面打开后等待叠加线出现的时间。

主体代码放在立即执行函数中，并启用严格模式，避免变量污染目标网页的全局作用域。

## 3. 配置和运行状态

第 17～44 行集中保存基础配置：

```javascript
const ACTIVE_REFRESH_MS = 15_000;
const IDLE_REFRESH_MS = 300_000;
const MOUNT_RETRY_MS = 500;
```

- 交易时段或尚未拿到数据时，每 15 秒刷新；
- 非交易时段每 5 分钟刷新；
- 尚未找到成交额图时，每 500 毫秒重试挂载。

`API_HOSTS` 按优先级保存三个接口域名。`INDEXES` 保存两个指数的名称、`secid`、线条颜色和填充色：

| 配置键 | 显示名称 | secid | 颜色 |
| --- | --- | --- | --- |
| `allA` | 全A等权指数 | `47.800004` | 紫色 |
| `average` | 平均股价 | `47.800005` | 青绿色 |

两种指数只在配置上不同，请求、解析和绘图逻辑完全复用。以后如果接口提供了另一个可用指数，可以在 `INDEXES` 中添加配置，再由现有按钮生成和绘图流程处理。

第 46～58 行保存运行状态：

- `activeKey`：当前选中的指数，默认是 `allA`；
- `dataByKey`：分别缓存两个指数已经获取的数据；
- `loadingKeys`：记录正在请求的指数，防止重复请求；
- `statusByKey`：分别记录加载中或加载失败状态；
- `targetCanvas`、`overlayCanvas`、`switchPanel`：保存原图、透明叠加层和切换面板引用；
- `hoverSlot`：当前鼠标指向的交易分钟；
- `mountTimer`、`refreshTimer`：挂载重试和行情刷新定时器。

## 4. 行情接口请求

### 4.1 请求方式

`requestJson()` 优先调用 `GM_xmlhttpRequest`，请求超时时间是 6 秒。油猴环境不存在该 API 时，再降级使用原生 `fetch()`，便于本地测试。

测试页会设置 `window.__EMA_MARKET_INDEX_MOCKS__`。如果检测到模拟数据，函数直接返回对应 `secid` 的模拟响应，不访问网络。

### 4.2 接口地址和字段

`apiUrl()` 生成以下形式的地址：

```text
https://{hostname}/api/qt/stock/trends2/get
```

主要参数：

- `secid`：区分全A等权和平均股价；
- `fields1=f1,f2,f5,f8`：请求基础行情字段，返回中使用名称和昨收；
- `fields2=f51,f53`：请求分时记录中的时间和点位；
- `ut=fa5fd1943c7b386f172d6893dbfba10b`：东方财富网页行情接口使用的固定参数；
- `iscr=0`、`iscca=0`、`time=0`：与东方财富网页的单日分时请求保持一致；
- `ndays=1`：只取当天分时。

这和 `push2his.eastmoney.com/api/qt/stock/trends2/get` 属于同一个 `trends2` 分时接口族。脚本依次尝试：

```text
push2his.eastmoney.com
        ↓ 失败或数据不完整
push2.eastmoney.com
        ↓ 失败或数据不完整
push2delay.eastmoney.com
```

`fetchMarketData()` 会检查响应中是否有非空 `trends`，以及 `preClose` 是否是有效数字。只有三个域名全部失败后，才向上抛出错误。

## 5. 分时数据解析和交易分钟映射

接口中的单条记录类似：

```text
2026-08-24 09:31,6548.26
```

`parseMarketData()` 将它转换为：

```javascript
{
  time: '09:31',
  slot: 1,
  price: 6548.26
}
```

并和指数名称、昨收一起组成：

```javascript
{
  name,
  preClose,
  points
}
```

`minuteSlot()` 把交易时间映射为 0～240 的横坐标位置：

| 时间 | slot |
| --- | ---: |
| 09:30 | 0 |
| 10:30 | 60 |
| 11:30 | 120 |
| 13:00 | 120 |
| 14:00 | 180 |
| 15:00 | 240 |

午休时间被折叠到同一个位置，不占图表宽度。这样未收盘时，曲线只会画到当前真实时间，不会把上午的数据拉伸到 15:00。

## 6. 查找目标成交额图

`findTargetCanvas()` 不依赖网站可能变化的哈希类名，而是先查找稳定文案：

```text
今日两市成交
今日三市成交
```

找到文字节点后，脚本收集宽度大于 280、高度大于 180 的 Canvas，排除自己的透明 Canvas，再根据几何位置筛选：Canvas 必须位于成交额图例下方、横向覆盖图例，并且与图例的垂直距离不超过 500 像素。候选图中选择距离图例最近的一张作为成交额主图。

旧版本会在目标图尚未生成时一路向上查找父容器，并可能误选页面上方另一张面积更大的 Canvas。此时叠加层实际已经创建，只是挂在了别的图上，所以成交分析区域看起来一直没有显示。3.1.0 改为位置匹配；找不到位于图例下方的候选图时返回空并等待，不再退而选择其他图表。

这一定位方式能适应大部分页面结构调整，但如果网站修改了上述文字，或者不再使用 Canvas 绘制图表，就需要相应调整查找逻辑。

## 7. 创建透明叠加层

`attachOverlay()` 找到目标 Canvas 后，在它的父容器中加入：

- 一张绝对定位、覆盖原图的透明 Canvas；
- 一个居中显示的指数切换面板；
- 指针移动和离开事件；
- 一个监听原图尺寸变化的 `ResizeObserver`。

叠加 Canvas 使用：

```css
position: absolute;
inset: 0;
z-index: 20;
pointer-events: none;
```

`pointer-events: none` 让鼠标事件穿过透明层，避免破坏原 ECharts 的提示框和交互。

`prepareCanvas()` 会让透明 Canvas 的 CSS 尺寸与原图一致，并按设备像素比扩大内部像素尺寸。设备像素比最多取 2，既保证高分屏清晰度，也避免创建过大的绘图缓冲区。

## 8. 坐标换算和绘制

### 8.1 绘图区

`drawOverlay()` 根据当前页面成交额图的布局比例，计算上半部分折线图的绘图区：

```javascript
const left = width * 0.04;
const right = width * 0.04;
const top = height * (20 / 468);
const bottom = height * ((20 + 324) / 468);
```

指数线只覆盖上面的累计成交额折线区域，不进入下面的成交增减柱区域。

### 8.2 横坐标

横坐标按交易分钟计算：

```javascript
x = left + slot / 240 * plotWidth;
```

因此指数线与原成交额图共用 09:30～15:00 的时间位置。

### 8.3 独立涨跌幅纵轴

每个指数点先换算为相对昨收的涨跌幅：

```javascript
percent = (price / preClose - 1) * 100;
```

脚本取当前所有数据中绝对涨跌幅的最大值，最小范围为 `0.15%`，再向上取整到 `0.1%`，生成上下对称的纵轴。例如当日最大绝对波动为 `0.73%`，右轴范围会扩展为：

```text
+0.8%
 0.0%
-0.8%
```

对称坐标让 0% 始终位于图表中线，便于判断指数当前位于昨收之上还是之下。

### 8.4 绘图顺序

脚本依次绘制：

1. 0% 的虚线基准线；
2. 指数线与零轴之间的半透明渐变面积；
3. 紫色或青绿色分时线；
4. 最新点或鼠标指向点的圆形标记；
5. 右侧的上限、0% 和下限刻度；
6. 顶部面板中的当前点位和涨跌幅。

右侧刻度文字下方会先画半透明白色背景，减少原成交额曲线和网格线对文字的干扰。

## 9. 鼠标悬停

透明 Canvas 本身不接收鼠标，因此 `pointermove` 和 `pointerleave` 监听在原图父容器上。

鼠标进入上半部分折线绘图区后，`handlePointerMove()` 将横坐标换算为 0～240 的 `slot`，再从行情点中找出时间最接近的一条记录。随后重新绘制焦点圆点，并在按钮右侧显示：

```text
14:32 6548.26 +0.71%
```

同时，Canvas 的 `title` 会包含指数名称、时间、点位、相对昨收的点数变化和涨跌幅。鼠标离开绘图区后，显示恢复为最新行情。

如果鼠标指向的分钟晚于当前最后一条数据，脚本不会生成未来数据，而是继续使用最新行情点。

## 10. 指数切换和缓存

`createSwitchPanel()` 遍历 `INDEXES` 自动生成按钮。点击后由 `switchIndex()` 完成：

1. 修改 `activeKey`；
2. 清除旧的悬停位置；
3. 更新选中按钮颜色；
4. 如果该指数已有缓存，立即绘制；
5. 如果没有缓存，显示“加载中…”并请求数据；
6. 重置刷新计时器。

`refreshData()` 只在响应对应当前选中指数时重绘。假如用户先点平均股价、请求未返回前又切回全A等权，迟到的平均股价响应只会写入自己的缓存，不会覆盖正在显示的全A等权线。

后续刷新失败时，只要之前存在成功缓存，图上仍保留旧数据，不会因为一次临时网络错误清空整条曲线。

## 11. 自动挂载和页面重新渲染

脚本启动时并行执行：

```javascript
startMounting();
refreshData(activeKey);
scheduleRefresh();
```

即“请求行情”和“寻找成交额图”同时进行，而不是先后等待。图表和数据任一方先准备好都可以等待另一方，二者齐备后立即绘制。

如果初次没有找到目标 Canvas，脚本每 500 毫秒重试。`MutationObserver` 还会监听页面的节点变化，并以 100 毫秒防抖重新校验目标图。当东方财富因切换页面选项或内部重新渲染而替换原 Canvas 时，脚本会清理旧覆盖层和事件监听，再挂载到新的 Canvas 上。脚本还会每 5 秒做一次低成本健康检查，用于修复极少数未触发有效节点变化的页面重排。

这组逻辑解决了初版可能要等待较长时间才出现叠加线的问题。

## 12. 实时刷新策略

`isTradingWindow()` 使用 `Asia/Shanghai` 时区判断工作日和时间，不依赖电脑当前时区。活跃窗口稍微覆盖开收盘边界：

```text
09:25～11:35
12:55～15:05
```

刷新规则：

- 尚未获取到数据：15 秒后重试；
- 交易活跃窗口：每 15 秒刷新当前选中指数；
- 午休、收盘后或周末：每 5 分钟刷新；
- 页面处于后台：到点时跳过网络请求；
- 页面重新回到前台：立即确认挂载、刷新当前指数并重启计时。

调度使用递归 `setTimeout`，会等当前请求完成后才安排下一次请求，避免网络缓慢时多个请求重叠。

当前逻辑只区分工作日，没有单独读取交易所节假日日历。因此法定节假日的交易时间段仍可能按 15 秒尝试请求，但不会产生交易或写入操作。

## 13. 性能和安全边界

- 定时器只刷新当前选中的指数，未选中的指数使用缓存；
- 同一指数已有请求进行时不会重复发送；
- Canvas 重绘只处理当天约 241 个分时点，计算量很小；
- `ResizeObserver` 只在图表尺寸变化时重绘；
- 脚本只读取行情数据，不读取东方财富账号信息；
- 脚本不提交表单、不调用交易接口，也不执行买卖操作。

## 14. 可能受网站更新影响的位置

后续维护时优先检查以下位置：

1. 目标文字“今日两市成交 / 今日三市成交”是否仍然存在；
2. 成交额图是否仍使用 Canvas；
3. 上半部分绘图区比例 `20 / 468` 和 `324 / 468` 是否仍与网站布局一致；
4. `trends2/get` 的字段、返回结构和两个 `secid` 是否发生变化；
5. 油猴的 `@connect` 是否覆盖了新的接口域名。

如果按钮正常出现但没有曲线，优先检查行情接口。如果按钮和曲线都没有出现，优先检查目标 Canvas 定位和页面结构。
